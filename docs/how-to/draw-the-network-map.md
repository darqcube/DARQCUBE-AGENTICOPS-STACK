# Draw the network map

The **Network Map** dashboard shows your network as you draw it — boxes where
you put them, a line for every cable — with live traffic on each line, in
both directions, coloured by utilisation. It is a
[Network Weathermap NG](https://grafana.com/grafana/plugins/tamirsuliman-weathermap-panel/)
panel, generated by `make render` from a drawing file.

```
source-of-truth/map/*.yml  --make render-->  generated Network Map dashboard
   (your drawing)              (render-network-map.py)    + SNMP traffic per link
```

## 1. Draw

```bash
cp source-of-truth/map/examples/topology.yml source-of-truth/map/
```

```yaml
nodes:
  - {name: core-01,   x: 400, y: 100, icon: router}
  - {name: branch-01, x: 200, y: 300, icon: router}
  - {name: internet,  x: 400, y: -60, icon: cloud}
links:
  - {a: core-01:Gi0/0/1, z: branch-01:Gi0/0/0}
  - {a: core-01:Gi0/0/0, z: internet:uplink, bandwidth: 1G}
```

| Field | Meaning |
|---|---|
| `name` | an inventory device name — it then gets traffic and turns red when it stops reporting — or anything else to draw (a host, a provider) |
| `x`, `y` | pixels, `y` downwards, any origin |
| `icon` | `router`, `switch`, `server`, `pc`, `cloud`, `firewall`, or a path under the panel's `icons/` (e.g. `cisco/asa-5500`) |
| `a`, `z` | `<node>:<interface>`. On an inventory device: the SNMP **ifName** (as Devices & Interfaces shows it) — that interface's traffic is what the link shows |
| `bandwidth` | optional (`1G`, `100M`); default the interface's ifSpeed. Colours are percent of it |

Each link uses the end that is an inventory device: its out and in rates
become the two halves of the line. A link between two non-device nodes is
drawn without data.

The files are yours, like `devices.yml`: every `*.yml` in
`source-of-truth/map/` is read, and all of them are gitignored.

## 2. Render

```bash
make render
```

`make render` validates the drawing (unknown node, malformed end, duplicate
name) and writes
`observability/grafana/provisioning/dashboards/generated/network-map.json`;
Grafana picks it up within 30 s. With no drawing, the dashboard says how to
add one.

Do not edit the map in the panel editor: the next `make render` replaces it.
Move things in the drawing instead.

## Layout tips

- The panel fits the drawing to its width. To spread a crowded drawing, scale
  it vertically — `map: {scale: {x: 1, y: 1.6}}` — and the panel grows taller;
  scaling x (or both) only makes everything smaller.
- `map: {animation_seconds: 1}` sets the speed of the moving dashes (seconds
  per cycle, lower is faster).
- Draw from a tool that already has positions. For a containerlab lab, the
  VS Code extension saves its layout next to the topology
  (`<lab>.clab.yml.annotations.json`); converting that plus the topology's
  `links:` gives an exact copy of the lab diagram.

## Underneath

| Query (legend) | Feeds |
|---|---|
| `rate(interface_out_octets)` → `<device> <ifName> out` | a link half |
| `rate(interface_in_octets)` → `<device> <ifName> in` | the other half |
| `interface_speed` → `<device> <ifName> speed` | bandwidth when the drawing gives none |
| reporting or not → `STATUS <device>` | node colour |

The panel matches a link half to a series by its display name, which is why
the legends are fixed. The plugin is installed when Grafana starts
(`GRAFANA_PLUGINS`); air-gapped installs: [change-dashboards.md](change-dashboards.md).

Links the network reports by itself — LLDP neighbours and BGP sessions — are
listed under the map with their traffic, whether or not they are drawn.
